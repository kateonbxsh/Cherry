Variables

Variables in Cherry hold runtime values. A value always carries a type, and assignment checks assignability at runtime.

Declaring a variable in Cherry is quite similar to a lot of other languages:

TypeName name = expression;
// Example
int count = 0;
string label = 'ok';
Array<int> xs = new Array<int>();

You may also assign a value to a pre-defined variable.

target = expression;
count = count + 1;
user.name = 'Ari';
matrix[1, 2] = 42;

You can also perform an operation + assignment in one step by putting the operator before the = sign

target += expression;
target -= expression;
target *= expression;
target /= expression;
count += 1;
vec -= otherVec;

If a variable has been previously defined with a type, you can only re-assign values compatible with that type to it.

// fail: incompatible assignment
int age = 20;
age = "twenty";

Step-by-step: what happens when you declare a variable?

A declaration like this:

int count = 0;

typically happens in two conceptual steps:

  1. Create a variable binding named count in the current scope, with declared type int.
  2. Evaluate the initializer (0) to a runtime value, then check that it is assignable to int, then store it.

If the initializer fails (type mismatch, throws, etc.), the runtime should surface a clear error at the declaration site.

Step-by-step: what happens when you assign?

An assignment like:

count = count + 1;

typically does this:

  1. Resolve the target (count) in the scope chain.
  2. Evaluate the right-hand side (count + 1), including operator rules.
  3. Check assignability: the result must be compatible with the declared type of count.
  4. Store the value back into the variable.

Scope reminder: blocks create new variable worlds

Variables declared inside a block are not visible outside it. Shadowing creates a new variable with the same name.

int x = 10;
{
  int x = 99;
  Standard.println('inner={}', x);
}
Standard.println('outer={}', x);

Edge case: assignment into nested targets

Assignments are not limited to simple identifiers. They can target fields and indexers too.

Field assignment

user.name = 'Ari';

Recommended evaluation order:

  1. Evaluate user.
  2. Resolve member name (enforce access flags like private, readonly).
  3. Evaluate RHS ('Ari').
  4. Check assignability to the field type.
  5. Store.

Indexer assignment

matrix[1, 2] = 42;

If the target type defines a set[...] indexer, assignment should dispatch through it (and still validate types).

Edge case: failure types you should expect

  • Unknown name: assigning to a variable that does not exist in scope.
  • Readonly write: attempting to write to a readonly field or property.
  • Private/protected violation: illegal access depending on flags and inheritance.
  • Null access: user.name = ... fails if user is null.
  • Type mismatch: RHS not assignable to the LHS type.
