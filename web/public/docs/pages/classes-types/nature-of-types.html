Nature of types

In Cherry, types are runtime values. This is the mental model that unlocks the rest of the language. You are not only writing values of type int or string; you can also manipulate type objects themselves.

Types as values

The identifier int is itself a value. Its runtime type is type, and its value is the integer type object.

Standard.println("{}", int);         // prints type representation
Standard.println("{}", string);

The special case: type

type is also a runtime value of type type. In other words, type metadata is self-describing.

Standard.println("{}", type);

Classes are types

When you define a class, Cherry registers a new runtime type. Instantiation with new creates object values whose runtime type is that class type.

class Person {
  public string name;
}

Standard.println("{}", Person);      // type value
Person p = new Person();              // instance value
Standard.println("{}", p);

Failure mindset

If a name that should resolve to a type is missing from scope, you will get a name exception at runtime. That is usually a registration/scope problem, not a syntax problem.
